# 仓库隐私与安全测试目录

公开仓库保留运行代码、产品提示与技能、正式设计和可复现测试。私人对话、模型交接、原始审查资料、真实配置、凭据和使用环境截图保存在仓库外。技术文档中的验证数量属于对应批次记录，不表示综合回归或人工验收已经完成。

## 本地提交与 CI 检查

使用 Node 22 或更新版本，不需要安装检查依赖：

```sh
node scripts/install-privacy-hooks.mjs
npm run privacy
npm run privacy:history
```

安装脚本把检查器与政策快照放在当前仓库的共享 Git 元数据目录，设置本地 hooks 和 Node 位置；因此较旧分支及 linked worktree 也能使用同一护栏。检查器或资源核验政策更新后应重新安装。发现已有其他 hooks 配置或非本项目钩子时保留它并退出，维护者可接入已有流程。新克隆须主动安装 hooks，Git 不会自动信任仓库中的脚本。

提交检查读取完整暂存索引，包括此前已跟踪的文件；未暂存的修改不冒充将要提交的内容。推送前检查和 CI 检查全部本地可达分支、标签及其历史，而不是只检查最新文件。CI 必须取得完整历史；浅克隆不能提供历史清理证据。`node scripts/privacy-check.mjs --history --all-objects` 另检查本地未引用 blob，适用于历史清理后的核验。

检查输出仅含文件、行号和类别，不输出匹配值。常见凭据格式、私人用户目录、原始对话标记、私人记录文件及模型交接过程会被拒绝。产品 persona、规范提示、通用安装占位符、公开技术说明和可识别的虚构测试数据仍可使用。模式检查不是恶意代码沙箱或所有秘密的证明，不能替代人工内容审查。

二进制资源需先核验可见内容和元数据，再在 `scripts/privacy-policy.json` 的 `reviewedBinary` 中登记路径、SHA-256 和简短核验理由。JSON 或 JSONL 对话转储也会阻断；明确的合成测试样本可经内容核验，在 `reviewedConversations` 登记同样的摘要与理由。内容变化会使旧核验失效，不能以目录为单位永久放行。真实凭据一旦误公开，应先撤销或轮换；只删除文件或历史不能撤回外部副本。

不要把备份、旧对象库、reflog、镜像或私人记录重新并入已清理历史。远端尚未同步历史时，取回旧分支可能重新引入已移出的内容；历史检查会阻止继续推送，须先制定远端与协作者迁移方案。

## 测试目录与隔离边界

`scripts/fixtures/test-paths.cjs` 是测试专用路径入口，不属于联机运行逻辑。默认测试基目录为系统临时目录下的 `noname-kit-tests`。可用 `NNK_TEST_ROOT` 指定专用目录，其目录名必须以 `noname-kit-test` 或 `nnk-test` 开头；不得指定仓库、用户主目录、磁盘根或已安装游戏根。Windows 只接受本地驱动器路径，拒绝 UNC 与设备命名空间；目录或祖先含符号链接或 NTFS reparse point 时拒绝。

所有临时 fixture 和进程配置位于该基目录的 `temp` 内，日志位于 `logs` 内。调用方指定的输出或 fixture 也必须位于边界之内；路径穿越、兄弟目录和错误的 fixture 前缀均拒绝。不要用放宽边界的方式修复路径报错。

真实 Loader 探针须显式提供独立的 `NNK_SOURCE_ROOT` 和基目录内的 `NNK_LOADER_PACKAGE`；源与已安装测试包不能是同一目录，否则比较无效。官方引擎只使用基目录内的隔离副本；可通过 `NNK_OFFICIAL_OLD_ROOT`、`NNK_OFFICIAL_LATEST_ROOT` 指定副本。程序化 Electron 运行壳也必须在隔离目录内准备。没有这些前置条件时应报错，不回退到个人游戏目录。

单元、隐私检查和路径检查可单独执行。官方进程、真实崩溃、ACL、文件事务发布与恢复探针需要专门授权和环境，不能因路径已参数化便自动运行。清理仓库不解除新旧补传暂停，不改变当前提议的“是”授权、整批事务或重启门禁。
